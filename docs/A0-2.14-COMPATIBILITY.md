# Agent Zero 2.14 compatibility — 13 October 2026

## Required correction

Published Local Guard 0.9.3 predates the Responses extras snapshot introduced by Agent Zero 2.14. The candidate on this branch filters `responses_history_context` before provider dispatch, including prefix/prompt, replay groups and extras. Both guarded model wrappers and the direct tool-model result hook check `LLMResult.history_extras` before it can enter persisted history metadata. The field check remains compatible with 2.13, where that result field does not exist.

An offline regression using the actual 2.14 Responses request builder showed that a synthetic email in structured context extras could enter the projected provider request unchanged. Two additional cases showed unchanged emails in returned extras metadata. All three failed with 0.9.3 and pass with the correction. The existing Secret check already blocked a synthetic password in the same input side channel. These are synthetic reproduction cases; no real user-data disclosure was observed or inferred.

Do not treat the published 0.9.3 ZIPs as complete 2.14 acceptance evidence. This candidate needs to be included in the next coordinated suite release. Model routes, default detector, profile grants and activation decisions are unchanged. No changes were required in the Gateway or Manager runtime in the tested scope.

- 39 frontend tests passed.
- 228 focused upstream tests passed: installed-SDK loopback HTTP transport, Responses replay/extras, plugin asset precedence, subordinate lifecycle/profiles, history, native call repeats and dependency migration contracts.
- Six supplementary checks exercised real child context tasks at one/two delegation levels: masked policy, granted unmasked policy, and revoked-root rejection.
- Existing A0 2.13 framework: 175 Local Guard tests passed; three checks for 2.14-only fields explicitly skipped.
- Fully active native-preset integration with simulated provider dispatch: Main/Utility input and output masked, exact local roundtrip, Secrets blocked before dispatch, ordinary disable of all three required components rejected.
- Actual browser/HTTP: readable healthy Manager diagnostics, four native presets, configuration modal rendered, Developer profile/grant/new chat, profile switch away/back, revoke and chat deletion. No model messages were submitted. Revocation enforcement is covered by the native policy tests; these UI operations alone do not prove an autonomous attack-defense scenario.

All seven previously captured synthetic configuration/mapping files remained byte-identical. This migration instance retained published suite 0.9.3 and was used for update/state-preservation validation, not as evidence that the unpatched release closes the extras gap.
- Original installation on port 59022 remains on 2.13; all 105 originally protected files remained identical.

## Limits

No paid Requesty calls, real provider inference or Ollama generation; all model transports were simulated or used loopback HTTP fixtures. No general prompt-injection guarantee, provider-side correctness, Windows-native certification or autonomous browser/form acceptance is claimed. Existing image/raw-tool-transfer boundaries remain. The previously reviewed Infection Check behavior is not changed by this patch; it was not activated. Deprecation warnings from upstream Pydantic/LangChain/LiteLLM are present but did not fail these checks.
